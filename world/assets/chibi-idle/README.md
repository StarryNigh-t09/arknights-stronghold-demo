# 干员 Q 版小人 · 待机（Idle）定帧

PRTS 干员页「干员模型」SpineViewer 导出的**待机动作**定帧：模型视角选 `正面`（战场骨架，带武器），动作列表点 `Idle 待机`，把时间轴拖到**动画中点帧**（如 60 帧动画取第 30 帧），背景切「透明」，点「导出 PNG」。

- 生成时间：2026-11-13
- 数量：**144 个 `<干员名>.png`**（`world/data/portraits.json` 的 143 个 key 全覆盖 + 手动补的 `能天使`）
- 目录：`coopanion-arknights/world/assets/chibi-idle/`
- 体积：27.9 MB，单张约 205 KB（均值）
- 未拿到：**无**，143/143。唯一没做的是**时装皮肤**（见第 4 节）

| 项 | 值 |
|---|---|

## 2. 与另外两份的实测差异（像素级，阈值 max|Δ|>8 记为不同）

对比基准：`../chibi-battle/`（正面 + Default 默认姿态）与 `../chibi/`（基建 + Relax）。

| 对比 | 中位差异 | 范围 |
|---|---|---|
| 本份 vs 战场正面 | **1.23%** 像素 | 0% – 12.27% |
| 本份 vs 基建 Relax | **8.02%** 像素 | 0.80% – 18.08% |

- **姿势**：同为站立，但待机循环中段是「呼吸/微晃/重心偏移」那一瞬，不是骨架的默认 T 姿——所以肩膀、披风、尾巴、武器有细微位移；个别干员动得大（`迷迭香` 12.27%、`山` 11.23%、`浊心斯卡蒂` 9.18%、`归溟幽灵鲨` 8.29%、`薇薇安娜` 8.03%）。
- **朝向**：与战场正面完全一致（同一骨架、同一视角），不存在 left/right 两套。
- **武器**：带武器，与战场正面一致；和基建 Relax（无武器）是根本差别。
- **46 个干员**与战场正面图差异 <0.05%（`圣聆初雪`、`Mon3tr`、`霜叶`、`褐果`、`哈洛德`、`折桠`、`幽灵鲨`、`野鬃`、`慕斯`、`角峰` 等）——这些人的默认姿态本身就和待机中点几乎重合，等于重复素材。

**结论**：这份不是新视角，而是「同一正面骨架 + 待机动画的另一帧」。真正带来新信息的是那 97 个动作幅度较大的干员；对 46 个几乎零差异的，用 `chibi-battle/` 即可。

## 3. 三个特殊条目

| 干员 | 情况 |
|---|---|
| `浊心斯卡蒂` | 视角选项是 `战斗 / 基建`（没有「正面」），按 `战斗` 导出 |
| `盟约·辅助干员` | 只有 `正面 / 背面`，模型本身是持枪士兵；动作表里有 Idle，导出的仍是士兵 |
| `“暴躁铁皮”` | 只有 `正面`，模型是一台机器 |

## 4. 时装皮肤没有导

页面顶部有「时装」chip（例如灰喉有 `默认` / `归巢`），可切皮肤。本次**只导默认皮肤**，一是 143 人 × 多皮肤耗时成倍，二是需求里没指定哪些皮肤。要补的话：在 `_chibi_idle.tpl.js` 的 `PICK` 之后加一步——点第 2 个 `.ak-chip`，输出文件名改成 `<名>__2.png`，其余不变。

## 5. 复现

脚本：工作区根目录 `_chibi_idle.tpl.js`（`__NAMES__` 换名字数组，交 `ego_script`）。关键步骤：

1. `page.goto('https://prts.wiki/w/' + encodeURIComponent(名))` → 点 `#spine-root .sv-load button`（载入模型）
2. 第一个 `select`（aria-label=`模型`）选 `正面`（回退链 正面→战斗→基建→背面）
3. 点 `title="背景：透明"` 的色块
4. 在 `.sv__anim` 行里找文案匹配 `/待机|Idle|Relax/` 的行并点击（回退 `/Default|默认/`）
5. `input[type=range].sv__seek` 的 value 设成 `floor(max/2)`，触发 `input`+`change`
6. 劫持 `URL.createObjectURL` 拿 blob、吞掉 `HTMLAnchorElement.prototype.click`，点文案为 `PNG` 的按钮，等 2.6s

实测 7–8 秒/人，`ego_script` 单次 120 秒上限约 12 人，143 人约 18 分钟。
