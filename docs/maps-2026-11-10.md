# 地图库：从 PRTS 与实机两侧建格子

日期：2026-11-10 · 状态：**部分完成**（PRTS 图已下、实机格与地形采集脚本已就绪，批量采集待跑）

## 为什么要两套坐标

- **PRTS 图**（910×512）用来认图与离线规划：它和实机是同一张渲染，但取景不同，不能直接拿来点。
- **实机格**才是能点的坐标：休整期抓住一个干员时，所有可部署格会变绿，`sidecar/freetiles.py` 把绿色区域切成格心，得到的就是 1920×1080 下的可点格。
- 格子几何常量（实机，标准镜头）：`anchor = (660,300)`、`step = 110`、`cols = 8`、`rows = 5`，来自 `world/data/maps/wz-01.json`。

## 已落盘

- `world/assets/maps/wz-01-f1.png`、`-f2.png`、`-f3.png`：PRTS「卫戍协议规程 战场01」三张场地图（910×512，639/596/644 KB），来源 `media.prts.wiki`。
- `world/data/maps/wz-01.json`：`{ anchor:[660,300], step:110, cols:8, rows:5, deployable:33, gates:{red:[],blue:[],note:'未标定'} }`。
- `world/sidecar/freetiles.py`：抓取态绿格 → 格心（阈值 0.55，NMS 70px）。
- `world/scripts/_map-capture.mjs`：一次采集 = 折商店 → 抓取态扫格 → 普通帧取色 → 分类 `ground/high/rock/gate_red` → 写 `world/data/maps/wz-01-live.json`。

## 分类依据

| 类型 | 判据 |
|---|---|
| ground | 沙色系，R>150 且 G>125 |
| high | 高台浅青，G > R+6 且 G > B+4 |
| rock | 其余（岩石/水面/装饰） |
| gate_red | 该格 36×36 内 R>170 且 G<90 且 B<90 的像素占比 > 25% |

阈值是 2026-11-10 晚在实机帧上试出来的第一版，还没做多帧校准；采集时会把每格的 rgb 与 red 比值一并存盘，便于事后重分类而不必重新采集。

## 还没做

1. 三张场地逐张采集（需要连续 3 局或 3 次不同场地，因为场地是随机分配的）。
2. 蓝门定位（目前只做红门；蓝门是出生/漏怪点，形状是蓝色立方体，判据待定）。
3. PRTS 图与实机格的仿射对齐（用于「看 PRTS 攻略 → 落到实机某格」）。目前只能靠人看图对位。
4. 多镜头适配（拖到边缘会平移镜头，`anchor` 会失效；现在的做法是每回合重新扫格，不依赖固定 anchor）。
