## 2 机制事实（代码为最终口径）
- **坐标口径**：游戏 1920x1080；minitouch 触摸屏是竖的 1080x1920，`raw_x = 1079 - y, raw_y = x`。写反=「点了没反应」。
- **商店展开/折叠判定**：`sidecar/ocr.py` 裁 (400,860)-(1600,1060) 求均值，**< 300 判为展开**。展开钮 (1770,1005)，收起钮 (1763,953)。折叠后整套甲板右移 40~150px，**折叠态量的甲板坐标一律作废**。
- **按钮**：升级 (337,972)（x 必须按最左卡边缘算，Lv2 五格实测 337）；刷新 (1763,686)；冻结 (1540,686)（整排冻结，一个方框都能按）；准备就绪 (1774,166)；开战 (916,54)；回大厅 (1753,1004)；断线重连 (1685,975)。
- **商店卡位**：y=910，x=755/997/1236/1476（格数=3+中心等级，升级后就挪，优先用 OCR 卡心）。
- **甲板（折叠态）**：干员 10 格 x 217→1551、步长 148.2，y 911→921（透视）；装备 5 格 y=775、步长 142。拖走不重排。
- **手势参数**：`DECK_PICK_HOLD_MS=600`（50ms 被当单击弹详情；90ms 拎不动、120ms 能拎）；`PICK_DWELL_MS=150`（按下后到开始滑之间的停顿）；`ARRIVE_DWELL_MS=450`（到格心后、松手前）；`PHANTOM={dx:33,dy:120}`（手指落点=目标格心+偏移）；`DECK_PICK_DY=-21`。**minitouch 连续两行 `w` 后者覆盖前者**，停顿必须并进前一个 `w`。
- **上场配方**：d→c→w(hold+PICK)→10 段×45ms→w(ARRIVE)→u→c→w150；再 d 格心、朝目标滑 70px（6 段×40ms）→w250→u 定朝向。
- **买卡节奏**：选中 800ms → 确认 1100ms（写死坐标版 1200/1500）；升级两下 1200/1500（第一下只是把按钮变「确认升级」）。
- **甲板扫描**：`sidecar/deck.py` 找干员头顶阶牌，按压点=牌心+(52,99)；按牌间距挑行（甲板 142~148，商店 243），取 y 最大那行；折叠态必须传 `minPressY=840` 挡掉战场幽灵行。
- **上限**：整备区 10、装备 5（不占部署位）；wz-01 可部署格 19 个。
- **环境**：adb `C:\Program Files\Netease\MuMu\nx_main\adb.exe`、serial `emulator-5556`；截图只能 `shell screencap -p` + pull（`exec-out` 会被 CRLF 弄坏）。ops_bash 仍报 `EXECUTOR_UNAVAILABLE … awk.exe`，唯一通道是 run_code 里的 node fs / child_process。

## 3 失败模式与已证伪的假设
1. **「某两格不能放」——证伪**。`world/data/map-issues.jsonl` 79 条「牌没离手」铺在 15 格：1196,353 x15、725,347 x10、692,667 x9、1342,552 x7、1360,665 x7、1489,665 x7、964,350 x6……失败起手点集中在甲板右侧 1562,882 / 1413,882 / 1407,771 / 1360,636，同一起手点时成时败 → 是起手/长按/落点判定问题。
2. **「起手按得不够久」——证伪**（seq12276）：缺的是到位置之后的停顿。修法是把 `ARRIVE_DWELL_MS` 写进最后一段滑动的 `w`，而不是加长 hold。
3. **adb input / sendevent / draganddrop 全废**：只能把干员「抓起来」，松手永不落位（试过 6 个起手点、3 种时长、写 /dev/input/event4）→ 换 minitouch 文件模式。
4. **定朝向滑 600px**：游戏当成「把干员挪到别处」，落到非法格后卡在「按住等落位」——左侧弹面板、右侧显示出售、准备就绪点不动。缩到 70px，收尾补一次点空地 (1700,250) 取消选中。
5. **商店展开时拖动无效且带偏镜头** → 拖甲板前必须先折叠。
6. **deck.py 的 best 会把装备甲板当干员甲板**：2026-11-11 16:0x 从装备行拖了 2 次，格差 28/58 看着像成功，整备区张数没变。
7. **空甲板时 deck.py 从战场 y≈672 抠出一行假牌** → 反复拖同一个幽灵点、4 个格子全失败还报「整备区 1 张」。

## 4 决策规则（`world/lib/restplan.js:planRestStep` 是唯一真源）
阶梯：第1回合规则 → 阶数必买 → 第2回合规则 → 升级 → 买想要 → 差钱冻结 → 凑对子买 → 刷新 → 兜底买 → 装备 → stop。
- `PACE`：1@1、2@3、3@4、4@7、5@10，**永不升 6**（六本池脏，停五本碰六本）。
- 常量：`BENCH_CAP=10`、`EQUIP_CAP=5`、`REFRESH_SAFETY=40`（安全阀，非策略上限）、`REFRESH_BEFORE_BUY=3`、`EQUIP_CAP_FIRST=3`（整局先买 3 件装备）、`UPGRADE_SOFT_RESERVE=2`。
- 冻结只有一个条件：店里有想要的卡但钱不够；其余一律刷新或停手（都烂不冻结）。三连免费商店只买不刷。
- 钱**当回合花光**，不攒钱（seq11655）。整备区满 → stop，不卖人（卖人属决策层，待定）。
- 排序 `pickWanted`：已有张数多 → 清单命中 → 便宜 → 名字。
- 整备区满 10 或钱花光才 stop；冻结执行完本回合结束（第2回合例外，冻结后接着升级）。
