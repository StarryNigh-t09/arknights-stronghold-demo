## 二、当时以为没打通的：拖上场

2026-11-10 07:40 复测：不是手势问题，是这里根本不需要拖，自动部署。

### 现象
- 甲板上的干员拖到地图格，**大部分时候没反应**；偶尔成功一次（`(1565,860)→(1200,397)`、"剩余可放置角色" 8→7）。
- 成功后 `placeUnit` 的两步滑（拖上场 + 定朝向）是照 MAA `BattleHelper.cpp:409 deploy_oper` 写的：首次 swipe `dist/1000*400ms`、停 200ms、朝方向再滑 600px/150ms。

### 今晚试过、都不稳定的注入方式

| 方式 | 结果 |
|---|---|
| `sendevent` 逐条写 `/dev/input/event4` | **完全不被游戏接受**：evdev 里事件确实进去了（88 行、时间戳正常），但游戏毫无反应 |
| 一条 `printf` 写整段 `struct input_event` 字节 | 同上，接口层收货、游戏不认 |
| `input tap` / `sePress` | ✅ 有效（点按钮、点卡、弹详情都行） |
| `input swipe` | 时灵时不灵；700ms/1200ms 都试过，**偶尔进拾取态**（格子变绿、出现攻击范围菱形、「点击取消」） |
| `input draganddrop` | **能稳定抓起**（进拾取态、干员跟着走），但**松手不落位**，直接退回甲板 |
| `input motionevent` 拼 DOWN/MOVE/UP | 无效 |

### 关键卡点
进了拾取态之后，**松手不落位**。用户说过「拖到位置松开 → 再长按拖向朝向 → 松开」，
但第二步（长按 + 拖方向）今晚没能让它生效：拖了不出朝向箭头，松手退回甲板。

MAA 的解法是它自己实现的 `swipe()`（MaaFramework 的 input 层，走 minitouch 一类的协议），
不是 adb `input`，也不写 evdev —— 所以这块**抄不到**。

## 二点五、【重要】不拖也能上场 —— 自动部署

第 4 回合战斗截图里发现：甲板上买来的干员（黑角、桃金娘）**自己在战场上出现了**，
而今晚从没成功拖过任何一次。对照 PRTS `data/protocol.md` 的规则：

> 整备区位置 = 作战阶段部署顺序，从上到下、从左到右自动部署，部署不消耗费用。

所以 **手动拖只是「提前布阵 / 改朝向」，不是上场的必要条件**。
这意味着拖拽问题是「锦上添花」，**不阻塞整局流程** —— 今晚的 7 回合就是这么打出来的。

结论修正（2026-11-10 07:40 最终版）：拖拽不用再调，默认就不拖 —— `autoRest` 只在
显式 `deploy: true` 时才调 `deployFromDeck`，整局靠游戏的整备区自动部署。
把「买卡 → 战斗 → 结算」的稳定性先压实。
