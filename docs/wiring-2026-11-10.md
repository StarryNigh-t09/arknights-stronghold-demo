# 变更说明：社区攻略数据接入决策层（2026-11-10）

## 改了什么（一句话）

五份社区攻略 JSON（economy / covenants / runflow / guides / live）从 world/data 接进 knowledge → decide → drive → tools：买卡排序、升级费、休整期提示、干员技能/定位、盟约评级开始吃社区数据；只接线。

## 数据从哪来

| 文件（world/data/） | knowledge.js 读取者 | 消费方 | 影响 |
|---|---|---|---|
| economy.json | economy() / levelupCostTable() | drive.autoRest、tools.wz_advise、section=economy | 升级费与节奏问答 |
| covenants.json | covenantBook() / covenantStrength() / covenantPick() | decide.covenantBonus、adviseDraft、drive、tools 的 op/covenant | 盟约加分、8 条选卡建议、评级展示 |
| runflow.json | runflow() | adviseRest 的 checklist、drive、tools op、section=runflow | 提示条、定位、买卡优先级 |
| guides.json | guides() | section=guides、search() | 攻略要点查询 |
| live.json | liveNotes() | section=live、search() | 主播实测查询 |

## 具体改动

### world/lib/knowledge.js

- `readData(name, fallback)`：按 world/data → assets → 仓库 data/ 找文件，全无则返回 fallback，不抛错。
- `economy()` / `covenantBook()` / `runflow()` / `guides()`：整段读取，缺省为空结构；`liveNotes()` 13 条。
- `levelupCostTable()`：只收 money > 0，转成 `{升前等级: 花费}`，当前 `{"1":5}`（JSON 的 level 是「升到第几本」，键取 level-1）。
- `covenantStrength()`：26 条 `{名: {tier, rating, kind}}`；`covenantPick()`：按 rank 排，8 条。
- `operatorTech(name)`：查 skillSwap 133 条，返回 `{skill, tier, evidence}`，先剥掉「哲亚(?)」这类存疑标记。
- `index()` 追加盟约评级/选卡建议/原则/开局/常见错/买卡优先级/单位评价/升级节奏/花钱/阶段/直播 11 类，`search()` 可同时命中 PRTS 与社区内容。

### world/lib/decide.js

- `DEFAULT_LEVELUP_COST = {1:5, 2:4, 3:6, 4:8, 5:10}`。
- `levelupTableFromEconomy(rows, base = DEFAULT_LEVELUP_COST)`：有数额的行覆盖 base，键 `Math.max(1, level-1)`；null 跳过，不猜 0。
- `COVENANT_TIER_WEIGHT = { S:1.5, 'A+':1.1, A:0.8, 'A-':0.6, 'B+':0.3, B:0, 'B-':-0.5, C:-1.5, D:-2 }`；`covenantBonus()` / `adviseDraft()` 用它加权。
- `tierValueOf(tier)`：1–6、`'3'`、`'三阶'`、`'III'` → TIER_VALUE `{1:1, 2:1.6, 3:2.4, 4:3.4, 5:4.6, 6:6.0}`，认不出 0。
- `checklistFor(action)`（adviseRest 内）：按动作正则从 buyRules 取 ≤3 条进 checklist，不改 action。
- `targetLevelFor(round)` 仍用写死的 `LEVEL_PLAN = [[1,1],[2,2],[4,3],[5,4],[8,5],[10,6]]`，economy.json 只供钱。

### world/lib/drive.js

- `autoRest()`：以 `levelupTableFromEconomy(economy().levelup)` 为底表，`st.upgradeCost` 读到就覆盖 `levelupCost[level]`；另给 `adviseRest` 传 `covenantStrength()` 与 `runflow().buyPriority`。

### world/src/tools.js

- `sectionText(section)`：整段输出 economy / runflow / guides / live / pick。
- `wz_know` 新增 `section`，enum `['economy','runflow','guides','live','pick']`；op 带「技能建议」「定位」，covenant 带「社区评级」。
- `wz_advise` 补 `covenantStrength()`、`runflow().buyPriority`、`levelupCostTable()`。

### world/src/ENV_PROMPT.md

- 「实战要点」后加约 200 字：wz_know 用法 + 社区数据引用规矩。

## 为什么这么改

7 回合只有 4 人阵容，表层是拖上场没通（world/docs/NIGHT-2026-11-10.md 记了 6 种注入方式）；决策层这边的根因是数据没接线：五份 JSON 2026-11-09 就整理好，knowledge.js 注释原话「这些文件以前只躺在 data/ 里没人读，决策层等于只有 PRTS 的表 + 手写常量」。买卡只按等阶和盟约人数算，查干员只给特质，社区评级/技能建议/实测升级费/主播操作都进不了判断。这次接线后，同一套数据既影响排序，也影响回答。

## 边界与风险

- **社区评级不是游戏内数值。** S/A/B/C 来自主播口播和字幕，会过时、会互相矛盾，只作排序权重；引用要带来源，别当官方数据。
- **economy 升级费底表会被 OCR 覆盖。** 底表只有 1→2=5，其余默认 4/6/8/10；autoRest 每回合用 `st.upgradeCost` 覆盖，读不到才用底表。
- **路径回退 world/data → assets → 仓库 data。** 全找不到时返回空结构、查询静默输出空表；发布包漏带五份 JSON 时会退化。
- **升级节奏仍写死 LEVEL_PLAN。** 改 economy.json 的 round 不会自动改节奏，两份要一起改。
