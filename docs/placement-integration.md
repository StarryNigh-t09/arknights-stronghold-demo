# 站位自动化：从「有空格就塞」到「按职业和范围挑」

日期：2026-11-10 中午　作者：阿渊　状态：打分器与计划器已完成并有测试，接线差「认人」这一环

## 1. 现状（为什么要改）

第二局全自动跑下来：R1–R8 零掉血，R9 起每回合掉 10，R10 结算。
掉血不是因为没上场（甲板到场上一直是自动拖到位），而是**上场位置是写死的 12 个屏幕坐标**，
按「第一个空格塞第一个干员」的顺序填，跟职业、攻击范围、敌人来向都没关系。

## 2. 已经有的零件

| 文件 | 内容 |
|---|---|
| `world/data/operator-ranges.json` | 143 个干员的职业 + 攻击范围格集（`[[dx,dy]]`，`[0,0]` 是自身格），来自 PRTS Widget:Range 的 SVG 还原 |
| `world/lib/placement.js` | 纯函数打分：`coveredCells` / `scoreAt` / `bestPlacement` / `planDeploy`，以及屏幕像素 ↔ 网格换算 |
| `world/test/placement.test.mjs` | 12 条测试（含像素换算往返、狙击抢能罩住路线的那格、closed 过滤） |

打分公式（用户的约束：范围重叠不算缺点，所以没有重叠惩罚）：

```
score = 罩住路线格数 × 职业权重(path)
      + 医疗：罩住友军数 × w.ally
      + 重装/先锋：离红门越近越高（w.door × (6-距离)/6）
      + 远程站高台/栅栏、近战站地面 的加成
朝向 = 四个方向各算一遍取覆盖路线最多；平局朝红门
```

权重表（`CLASS_W`，相对值）：医疗 ally 2.5 最高；狙击/术师 path 2.0；重装 door 3.0；近卫 path 1.5 / ground 1.5。

## 3. 网格换算（新加）

休整期默认镜头下，可站格是 110px 见方的方格网，左上第一格中心 `(660,300)`：

```js
TILE_ORIGIN = [660, 300]; TILE_STEP = 110
pxToGrid([990,520])  // { gx: 3, gy: 2 }
gridToPx(3,2)        // [990, 520]
```

**镜头一动这组常数就失效**（早期踩过：同一点 09:55 能抓、10:03 抓空）。所以用之前要确认镜头没被拖过。

## 4. 接线怎么做（`deployFromDeck`，已留好口子）

```js
await deployFromDeck(deck, {
  smart: true,                 // 打开新逻辑
  identity: async (chip) => ({ // 认人：甲板小牌 → { name, cls, range }
    name: '灰喉', cls: '狙击', range: [[0,-1],[1,-1],[2,-1],[3,-1],[0,0],[1,0],[2,0],[3,0],[0,1],[1,1],[2,1],[3,1]],
  }),
  map: { path: [...], redDoor: { gx: 5, gy: 0 } },
  slotsLeft: 3,
})
```

打开后它先算出一份计划（谁上、站哪、朝哪），写进日志 `站位计划：灰喉→990,410朝right / ...`，
然后在原有循环里把「计划那一格」排到最前面试，失败才退回别的格子 —— 不改变拖拽手势本身。

没给 `identity` 就整段跳过，行为和现在完全一致（默认关闭，不会影响正在跑的对局）。

## 4.1 上场顺序（2026-11-10 中午补）

`guides-2026-11-10.json` 里有一条机制推导：部署顺序是自动的「从上到下 > 从左到右」，而敌人优先打**最后部署**的那名
→ 最后上场的那个是全场靶子。所以拖的顺序也要管：脆皮先上、承重装最后上。

- `placement.js` 新增 `DEPLOY_RANK` / `deployRankOf(cls)` / `orderUnits(units)`：
  医疗 2 < 术师 3 < 狙击 4 < 辅助 5 < 先锋 6 < 近卫 7 < 特种 8 < 重装 9（越小越早上）。
- **`planDeploy` 不重排**：返回的 plan 与入参 units 逐项对齐（plan[i] 是 units[i] 的落点），
  否则 chip 和落点会错位。重排只影响「先拖谁」，由 `drive.js` 在拖之前按 deployRank 排序（已接）。
- plan 每条多一个 `deployRank` 字段，日志里能看出这一拖是第几个上场的。

一轮下来：`npm test` 72 条全绿（decide 32 + offline 8 + wiring 17 + placement 15）。

## 5. 还差什么

1. **认人**：甲板立绘没有名字，只有等级小牌（Ⅰ/Ⅱ/Ⅲ）。抓 PRTS 143 张头像做模板匹配是当前方案
   （已派子代理产出 `world/assets/portraits/` + `world/sidecar/portrait.py`）。
   退路：轻按甲板干员会弹左侧详情面板，里面有名字，可以 OCR（未验证坐标，需真机试一次）。
2. **地图**：`path` / `redDoor` / `blueDoor` / 高台与栅栏格还没落成 `data/maps/wz-01.json`。
   最省事的做法是趁某回合「抓起一个干员」时截一张图 —— 那一刻全图可站格会变绿，直接算格心就得到可站格全集。
3. **职业分流的前提**是认人；认人之前，这套打分只能用到「路线覆盖」这一项。

## 6. 验收标准

- 计划日志里，医疗被排到最靠后（离红门最远）且罩住最多友军；
- 狙击/术师朝向覆盖敌人行进路线；
- 同一局 R9 之后不再出现「每回合固定掉 10」这种断崖。
