# 落位手势破案 + 起步时长实测（2026-11-12 凌晨）

结论先行：上一版「拖过去松手」永远上不去，因为**松手不是落位**——游戏会停在「待确认」态，
要再**朝目标方向滑一下**才算确认。这一步走通后，单次上场手势从 1.9s 降到 0.57s，且可稳定复现。

---

## 1. 真正的落位机制（真机逐帧验证）

一段完整的落位是三步：

1. **拎起**：按住待命区干员**精灵身体中心**（≈ 头顶徽章 + (47,88)），按住 20ms，分步拖到目标格。
   - 按在徽章 / 锁链 / 箱子上完全没反应；按太短（110ms）被当单击 → 弹「干员详情」面板。
2. **待确认**：松手后**不会自动落位**。画面变成：全场绿格 + 左上红「点击取消」+ 干员白色幽灵站在格上 +
   头顶出现 ∧ 箭头 + 白色菱形攻击范围。用绿格像素数判（`sidecar/_state.py` 的 `green`）：
   正常 ~30，待确认 10 万量级，阈值 3000。
3. **确认**：`adb shell input swipe (x, y-50) → (x, y-200) 400ms`（向上滑）。
   - **必须走 adb input swipe**，minitouch 发同样轨迹无效（事件密度不够，游戏不认）。
   - 实测松手（UP）事件确实送达内核（`getevent` 抓到 `ABS_MT_TRACKING_ID ffffffff`），所以不是注入问题。

判成功不能只看绿格归零（取消也会归零），要看**待命区少了一张牌**（或右上「剩余可放置角色」减 1）。

## 2. 起步按压时长扫描（54 次真机，全部进待确认）

同一张牌，moveMs=420 / 12 步，只改按住时长：

| 按住 | 结果 |
|---|---|
| 0 / 10 / 20 / 30 / 40 / 60 / 70 / 80 / 90 / 100 / 120 / 150 / 200 / 250 / 300 / 400 / 600 / 800 ms | **全部 3/3 进待确认** |

→ 起手按住时长根本不是关键，游戏看的是「按下后有没有连续移动」。
旧结论「90ms 拎不动」是因为当时只有单点 down、没有连续 move。

落点移动时长（hold=20）：150ms → 3/3（平均拖动 922ms）、220 → 3/3（956ms）、300 → 3/3（980ms）、420 → 3/3（1077ms）。

**定下来的配方**：hold 20ms + move 150ms + confirm 400ms ≈ **570ms 纯手势**（旧配方 600+1200+70px 定朝向 是其 3 倍）。

## 3. 端到端耗时（含截图 / OCR / 甲板复核）

| 阶段 | 单次耗时 |
|---|---|
| 纯手势 | 0.57s |
| 加「待确认帧」截图 + 像素判定 | ~1.2s |
| 加确认后复核 + 甲板重扫 | ~5.5s（2026-11-12 01:35 新局实测 5.5~5.8s/人） |

已做的压缩：
- `_state.py` 一次算完 green / red / 红X中心 / 商店亮度，另加 `--tiles` 顺带出合法格表，
  省掉一次 python 进程（约 1.2s）。
- 没拎起来时的重试**不再重扫甲板**（那一次根本没放上去，甲板不会平移）。
- 落点不合法时先换格、不换按压点（原来一失败就换点，每回合白花一次 5s）。

## 4. 合法格怎么来

待确认那一帧的绿格就是**这个干员**的合法格（`sidecar/_validtiles.py` 或 `_state.py --tiles`，
44x44 窗口绿占比 > 0.75，60px 去重，取前 14）。第一张牌进待确认时顺手学一次，后面的干员直接用。

注意：合法格**按干员类型不同**（近战不能站高台、远程能），所以学到的池只保证「对上一个干员合法」。
落错时游戏会把幽灵吸到最近合法格，确认前用 `snapTile` 按吸附格算真实落点即可（不额外花时间）。

## 5. 配额闸门：OCR 的 0 不可信

「剩余可放置角色」这个数 OCR 读得极不稳（同一帧把 6 读成 0、把 O 读成 0）。旧版逻辑「连读两次 0 就
本回合不布阵」直接把一整局玩死：整备区 10 张、场上空着，连读两次 0 → 4 个回合一个没放 → 掉血崩盘。

现在的口径：读 0 就**试放一个**。能上去＝有额度（继续一个个放）；上不去才算真没额度（收手）。
代价只是没额度时白花一次手势（约 5s），比整回合不布阵便宜太多。

## 7. 还没解决的

1. **朝向**：现在固定 `facing:'right'`，确认手势只是「向上滑」。方向轮盘还没真机验证过
   （资料说松手后滑方向＝选朝向，我们的实测里上滑就落位了，先按「上滑=确认」用）。
2. **卖人**：场上 10 个站满后配额恒为 0，新买的干员只能在整备区排队，整备区满 10 张后连卡都买不了。
   这是整局后期崩盘的结构性原因（02:01 截图 world/.tmp/r8.png：场上 10 个 + 「剩余可放置角色：0」+ 整备区 7 张）。
   已加临时闸门：整备区 ≥6 张时本回合不买。真正的解法是「卖掉低阶/位置差的干员腾额度」。
3. **装备**：`equipDeck` 还没在配额 0 的情况下跑过；这是不占名额提升战斗力的唯一途径。

## 8. 复现方法

```bash
cd world
node scripts/_grind.mjs 6        # 后台连打 6 小时（结算→大厅→新局→休整期→准备就绪）
node scripts/_stats.mjs          # 汇总上场成功率/耗时
node scripts/_peek.mjs           # 当前界面 + senseRun 原始读数（排查用）
node scripts/_deploy-only.mjs    # 只跑一次 deployFromDeck（不买卡、不点准备就绪）
```

关键文件：`lib/deploy-fast.js`（手势配方与常量）、`lib/drive.js`（deployFromDeck / 配额闸门）、
`sidecar/_state.py`（一帧定待确认 + 合法格）、`sidecar/deck.py`（待命区徽章定位）。
