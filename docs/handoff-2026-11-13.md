## 1. 用户的所有硬性要求（照抄原话要点，按主题归并）

### 1.1 决策层

| 主题 | 用户要求 |
|---|---|
| 升级节奏 | 严格按 `restplan.js` 的 targetLevelFor 节奏；**一回合可以只升级，但不要连续几回合只升级**，一般要在一个等级待 2~3 回合，Lv4/Lv5 可以待久一点 |
| 不升级的回合 | **必须补战力（买干员）** —— 因为「升级之后普遍就没钱买干员了」 |
| 前期/后期 | **Lv5 之前算前期**；前期凑三合一的优先级**略高于**盟约，后期反过来 |
| 三合一 | **有三合一就合成，不要为了等 Lv5 拖到后期**；三合一 = 干员变精锐（二级）+ 商店特殊刷新出三张免费高阶卡（**只能选一张**）；同时碰到「三合一」和「升级」→ 先升级再买三合一（免费商店能刷到更高阶）；4 级商店三合一可出 5 阶，5 级商店三合一可出 6 阶 |
| 商店等级 | 不升到 6 级商店，商店里**不会出 6 阶卡** |
| 刷新/冻结 | 「没想要的牌就刷、有想要的没钱就冻」；**钱多就继续刷新补强阵容** |
| 后期卡池 | **不要执着 2 费卡**（2 费普遍是 1 阶）；后期补盟约只用 **3/4/5/6 阶**；**1/2 阶只用来过渡前期和凑三合一，过渡完就可以卖掉，哪怕是 2 级卡** |
| 换人 | **用高阶换掉低阶**（买低阶卡无所谓，反正要换掉）；「重复干员检测是在**场上放满干员之后**再做」；换人优先按阶数、按能不能补目标盟约 |
| 盟约 | **只凑本局目标盟约**（不是随便凑）；主盟约只能在 **叙拉古 / 乌萨斯 / 莱塔尼亚 / 维多利亚 / 炎 / 谢拉格** 六家里选，别的不要选（要么难要么弱）；「盟约优先凑大的，其次输出类和经济类（精准/奥术/灵巧/奇迹），最后是防御类」；核心战力手段是**叠盟约，要尽量早开** |
| 战力来源 | 开盟约需要的干员主要靠**三合一**拿高阶，其次是商店刷新；「高级商店往往更难刷出低阶干员，得不偿失」「5 阶 6 阶都差不多，主要看怎么凑盟约」 |
| 卖人 | 「卖人可以等到缺钱的时候再卖」 |
| 装备 | 不是必须；**当前口令是「先不买装备」**；真要装时按属性分：加攻击→输出、加阻挡/生命→重装、同类取阶数最高、每人最多 2 件 |
| 布阵开关 | 默认开，只认显式的 `deploy:false` |

### 1.2 时间要求

- **每轮休整期尽量压到 70 秒以内**（当前实测 72~148s，仍不达标）
- 在保证成功率的前提下压缩时长，多跑实测，把结论写进决策层

### 1.3 站位规则（boss 关，第 14 回合）

- **每个 14 回合都是 boss 关**，阵容要大调；**boss 关部署格和普通回合一样**（所有地图部署位都不变）
- **x=7、8 放近战干员；x=5、6 放医疗和远程干员**
- **医疗要尽量覆盖到全部干员**；**远程干员的攻击范围要够到 x=9**
- **全部朝右（朝 boss）**
- **第 14 回合不执行升级，只刷新 + 买干员补强**
- 医疗细分：**行医（只能治前方）放 x=5；群奶（能顾到后方）放 x=6**；**护佑者（如淬羽赫默）也算奶**
- 普通回合站位：每张图给死的格，朝向要跟着给，**不要用覆盖评分去挑「最上排」**

### 1.4 操作语义（用户亲自示范并纠正过的）

- **换人 = 把整备区的干员部署到「另一个干员所在的格子」**；拖动 + 滑朝向都**必须**做
- 名额为 0 时**不能在空格上部署，只能在有干员的地方做换人**
- 松手在哪格就放哪格；如果那格有干员，被换的那个**回到整备区**（要保持原朝向）
- 场上干员之间互相拖 = **交换位置**（被换者保持原朝向）；**移动不占部署名额**
- 把场上干员拖回整备区长椅 = **撤回**，名额 +1
- **所有判定都按格子来**：整备区的小人要**单点它站的格子**才会弹名字面板，点小人本体不弹
- 拖拽要「稳」不要「快」：用户说「我能做到 1 秒 2 秒拖完，你应该也可以，多尝试找到稳定解」，但**一定要拖到位**

### 1.5 资料与流程要求

- 按森空岛攻略打（`https://game.skland.com/arknights/stronghold-guide`），**按干员职业摆放**
- PRTS 有全部地图，「下下来、像之前的方式划标号，我会告诉你哪些位置适合部署」——**后来改成：具体位置等匹到那张图再现场扫**，不用逐图标注
- **每次开局的禁用干员情况要扫一遍记起来**，抄攻略作业时要注意规避本局禁用
- 认人可以用 Q 版小人比对（PRTS 有小人模型），**要往下滑到「干员模型 → 载入模型 → 待机模型」那一层**；**只比对本局编队里有的干员**，注意同一干员的**不同皮肤**
- 以后问「还有没有疑问」→ **先把疑问回答完，再做**

## 2. 已证明是错的（不要这么做）

| 我曾以为 | 真相 |
|---|---|
| 「名额 0 时游戏不让换人」 | **错**。名额 0 只是不能放空格；拖到**已有干员**的格子能换，我几次误判让程序空转整回合 |
| 点小人本体认名字 | **错**。要点**它站的格子**才弹面板 |
| 装备拖到整备区 / 空格 | **错**。只有拖到**场上干员所在的格子**才立刻生效（不滑朝向、无待确认态） |
| 读顶部金币数字 | **错**，那个位置常读成 1。**读右下角徽章**才准 |
| 拖完立刻滑朝向 | 不稳（4 次 1 成）。**必须等确认帧**再滑 |
| 用「绿格像素数」判待确认态 | **错**。wz-01 这张图黄绿地块本身就绿（干净帧 green≈3400，真待确认只有 1874~2591），应改判**「点击取消」红徽章**（`cancel>0`） |
| 用整屏 OCR 找甲板名字 | **错**。整备区小人身上没有名字文字，名字只在详情面板和商店卡上 |
| 用方形头像模板比对认人 | 不可用（最好分 0.32） |
| 后期还买 2 费 1 阶卡 | **错**（用户明确禁止） |
| 为等 Lv5 拖着不合三合一 | **错**（用户明确禁止） |
| 先展开商店再布阵 | **错**。展开商店会把甲板和整备区整体顶走，坐标全错。**必须先折叠商店**（用户为这条骂过两次） |
| 用「标死格 / 冷却 / 次数上限」这类闸门掩盖失败 | 反思结论：坏做法。它让整回合静默收工，问题被藏住而不是修掉 |
| 同时开多个循环 / 多代进程 | 会抢同一台设备，minitouch 挂死。**同时只能有一个 oneshot 在跑** |

### 3.2 手势（唯一可靠的组合）

- 拖拽 `dragFromTo(from, to, {holdMs:650, moveMs:1000, steps:24})` → **落位 6/6 到格心**
- 换人：拖整备区小人 → 场上干员格，然后 `swipe(x, y, x+180, y, 420)` 朝右确认 → **4/4 成功**
- 装装备：拖装备图标 → 干员格，**不用滑**，立即生效
- 撤回：拖场上干员 → 长椅 (665,883)，名额 +1
- 售出：拖到右下售出区 (1770,920)；1 阶卖 +1 块

### 3.3 认人（当前唯一可用路线）

1. 逐张**点格子**（甲板 x 见上，y≈860）
2. 每点一次截一张图
3. `python sidecar/name_strip.py <stack.png> <stack.json> <shot...>` 把每张的名字小条（x0~230 / y233~322）竖拼
4. `python sidecar/names_ocr.py <out.json> <stack.png>` 一次 OCR（~4s）
5. 名字按 x 与甲板牌配对（全局最近优先，容差 150px）

5 张牌整套约 10~13s。**整备区张数读取经常不可信**（木台被商店遮住），要用账本兜底。

### 5.2 后台跑一局（唯一稳的方式）

```bash
cd ./world
export PATH=/c/Python314:$PATH COOP_OCR_PYTHON=C:/Python314/python.exe \
       COOPANION_PYTHON=C:/Python314/python.exe COOPANION_DEVICE=emulator-5556 \
```

- **billion-context 的 node（pid 4764）绝对不要杀**
- 日志：`world/_perf.log`（UTC，本地 +8）、`world/.tmp/verifyN.log`、`trace-night-<ISO>/steps.jsonl`（每代自建目录）

### 5.4 环境坑（会反复踩）

- `ops_bash` 每十来分钟撞一次 `EXECUTOR_UNAVAILABLE: ... winuxcmd.exe`（nlink 顶到 1024）。修法：用 run_code 的 node fs 遍历 `<DSH_HOME>/node_modules/dsh-ops/runtime/win32-x64/niubash/winuxcmd`（131 个文件），`nlink>900` 的 copy→校验→unlink→copy→unlink
- `python` 只有 `C:/Python314/python.exe` 可用（Store 启动器已坏：`NoInstallsError`）；**必须带 PYTHONPATH 且 cwd=coopanion**
- `read_image` 直接读 adb 的 PNG 会报 malformed，**一律先 PIL 转 jpg**
- `screenshot()` 偶发半张图（3 次重截），可 `adb kill-server / start-server / connect`
- run_code 里 `fs`/`cp`/`W`/`env` 这类名字声明过就不要再 `const`（`Identifier already declared`）
