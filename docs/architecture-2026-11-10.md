# 卫戍协议插件 · 操作逻辑与实现（2026-11-10 版）

> 一句话：**眼睛（OCR+视觉）认屏 → 状态机走流程 → 决策层算「这一回合该干什么」→ 手势层用 minitouch 精确点/拖 → 战报落盘 → 下一回合。**
> 全局没有任何「一路点到底」的盲操作：每一步都先认屏、认不出就停。

                                     ▼

                                     │                        │

                                     ▼                        ├─ run.js enterRun/playRound

## 1. 感知层：认屏

### 1.1 两条通道并行，互相校验

`senseRun(level)`（drive.js）一次调用做三件事：

1. `screenshot()` 拿 Buffer，写临时 png；
2. **OCR 通道** `readState(p, { level })` → `sidecar/ocr.py`（PaddleOCR + MAA 模型）读回合、资金、血量、商店卡名/价格/等级、剩余可放置数、调度中心等级、首格 x；
3. **视觉通道** `classifyBuffer(buf)` → `sidecar/vision.py`，把当前画面归到 `wz_hall / wz_admin / wz_db / wz_runinfo / wz_diff / wz_rest / wz_prep / wz_battle / wz_tactic / wz_settle / wz_joint` 之一，给距离值 `dist`。

融合规则：**视觉只在 `dist ≤ 0.12` 时才算数**，且只有当 `VISION_TO_OCR` 表里有映射、并且和 OCR 结论不同时才覆盖（原 OCR 结论存进 `st.screenOcr` 留证）。这样单通道抽风不会直接改状态。

> ⚠️ 已知坑：vision 偶发把休整期认成 `wz_admin/wz_hall`，覆盖掉 OCR 的正确结论 → autoRest 判「不在休整期」提前收工。已发生 3 次，**尚未修**（下一步改成「OCR 与 vision 都说是 rest 才算 rest」，或者把 vision 的 rest 类判定权重调高）。

### 1.2 为什么不用模板匹配干员立绘

甲板上的干员是 **Q 版小人**，PRTS 只有「头像 / 半身像 / 立绘」三个图族，拿 143 张头像做模板匹配，最小距离 0.185–0.238，和空地形块同一区间——**这条路死了**。改用「轻按干员 → 左侧详情面板 → OCR 大字名字」（见 §5.1）。

### 1.3 OCR 的稳定判据（踩过的坑）

- 血量读不到时返回 `null`，而 `Number(null) === 0`，旧代码把它记成「血掉光」。现在一律 `hp != null ? Number(hp) : null`，null 时补两次重试。
- 结算页「通过回合 13」会读成 `/|/|/`、`×160` 会读成 `X|6O` → 正则要收 `[0-9O|lI]`，且拿不到时用「打完回合数 − 1」兜底（结算恒比实际少 1）。
- `names_ocr.py` 输出的 box 是 `[x, y, w, h]`，**不是屏幕坐标**（被缩过），只能用来判「同样位置的那一行文字」，不能当点击坐标。

## 2. 手势层：minitouch

### 2.1 为什么必须 minitouch

`adb shell input tap/swipe` 全部试过，结论写进文档了：

| 方式 | 结果 |
|---|---|
| `input tap` | 能点按钮，**不能起选中态**，点甲板干员毫无反应 |
| `input swipe` | 起手无停顿 → 被当成「选中」，松手不落位 |
| `input draganddrop` | 能抓起，松手不落位 |
| `input motionevent` 拼 DOWN/MOVE/UP | 完全无反应（每次调用新建虚拟设备，跨进程的 DOWN 不延续） |
| `sendevent` 写 /dev/input/event4 | 游戏不认 |
| **minitouch `-f` 文件模式** | ✅ 唯一可用 |

设备信息：触摸屏 `event4`，Type B，`Xiaomi Touchscreen (1080x1920 with 32 contacts)`；坐标换算 `raw_x = 1079 − y`、`raw_y = x`（世界 1920×1080 竖屏横用）。
命令语法是 `d <contact> <x> <y> <pressure>`（我一开始写成 `d 0 <pressure> <x> <y>`，白折腾半天）。

### 2.2 三个已固化的手势配方

| 用途 | 配方 |
|---|---|
| **上场**（甲板 → 战场） | 按`牌心+(52,99)` → **长按 450ms** → 12 段 ×45ms 滑到`目标格+(33,120)` → 停 800ms → 松手 |
| **定朝向** | 从格心再长按 450ms → 朝目标方向滑 600px → 松手 |
| **卖卡** | 长按拖到 `SELL_ZONE (1840,860)` → 松手（实测金币 +1，甲板不重排） |

两个反直觉的点：

1. **长按 450ms 是必须的**。没有这个停顿，按下瞬间被判定成「选中」（左侧弹详情、镜头平移），松手弹回甲板。用户原话就是「光标放在角色所在格子，长按拖动」。
2. **幻影偏移**：拖起来后 Q 版小人画在手指**左上方** (dx=−33, dy=−120)，落位判定看幻影脚下。不补这个偏移，每次都是「拖到了但弹回去」。

> 甲板小牌：头顶那个「Ⅰ/Ⅱ/Ⅲ」方块是**卡的等级**（1 级卡/2 级卡），不是序号。检测靠 `deck.py` 找 28–55px 的深色圆角块连通域，实测牌心 (1338,595)/(1217,595)，按扣点 = 牌心 +(52,99)（牌本身按不动，必须按牌下方的干员身上）。

## 4. 休整期决策循环 `autoRest()`

最多 6 步，每步「认屏 → 算一个动作 → 执行 → 再认」：

```
for (step = 0; step < 6; step++) {
  1. senseRun();  screen === 'warbanner' → 等过场（最多 4×2.2s）
  2. 商店折叠？→ 点「展开」（最多 2 次，每次 1.4s 复核）
  3. screen !== 'rest' → 直接 return ok:false（不盲点）
  4. shop = toCandidates(OCR 的商店)；levelupCost = economy.json 的表（OCR 读到就覆盖当前级）
  5. adv = adviseRest({ money, centerLevel, round, shop, owned, 盟约… })
  6. 按 adv.action 执行：levelup / buy / reroll / freeze / 其它 → break
}
收尾：甲板还有干员 && 允许 deploy → deployFromDeck()
```

### 4.1 两道「甲板闸门」（这是 R9 崩盘的直接解药）

1. **剩余可放置闸**：`deck.length >= 剩余可放置数` → 再买就是买了一张必然上不了场、休整期结束被清空的卡（游戏自己弹「当前存在无法放置的单位，在休整期结束时将被清空」）→ 改为升级或直接结束。
2. **整备区上限闸**：`boardCount + deck.length >= DECK_CAP(10)` → 同上。而且整备区 > 10 时**任何拖拽都不会落位**（实测：卖掉一张回到 10，同一个拖拽动作立刻成功），所以这条闸也顺带修掉了「8 次拖拽全失败」。

### 4.2 买卡打分 `scoreCandidate()`

基线用**绝对强度**而不是性价比，因为**资金每回合清零**，省下的钱不会变成任何东西：

```
score = 2.0 × TIER_VALUE[tier] − 0.2 × cost
TIER_VALUE = { 1:1, 2:1.6, 3:2.4, 4:3.4, 5:4.6, 6:6 }   // 指数级，鼓励早拿高阶
```

在此之上的加减项（每一项都在 reasons 里写清来源）：

| 项 | 分值 | 依据 |
|---|---|---|
| 不在本局池子（`ctx.pool`） | **−∞** | 核心盟约没随机到就刷不出来 |
| 核心盟约成员 | coreFitOf | 决定全队上限 |
| runflow.units 18 张强卡 | +2.2 | 直播/攻略提炼 |
| runflow.buyPriority 命中 | +0.8 / 条（最多 2 条） | 社区优先级，只当提示 |
| **已持有 2 只（凑三合一）** | **+4.5** | 3 张同名 → 升精锐 + 一次免费高阶 |
| 已持有 1 只 | +1.8 | 同上 |
| 盟约协同（正向） | covenantBonus | 评级权重 S 1.5 … D −2 |
| 消耗品 | −12（钱 ≥ cost+6 时免罚） | 会烧掉，不该当默认首选 |
| 装备 | −3 | 装备位有限 |

**买不起不给 −∞**，只标 `affordable:false`——因为「值得留但买不起」正是该**冻结**的信号。

### 4.3 升级决策 `adviseRest()`

不是「有钱就升」，是「按表该到几本」：

```
levelupSchedule() = economy.json 的 {本数 → 最早回合}
   R2 → 2 本、R4–5 → 3 本、R5 前后 → 4 本、R8 → 5 本、R10 → 6 本
wantLevel = min(6, targetLevelFor(round))
canLevel  = centerLevel < wantLevel
         && money >= upCost + 3          // 升完必须留 3 块买卡
         && round <= totalRounds − 2     // 最后两回合不升，来不及兑现
levelScore = 4 + (晚于表 ? 2 : 0) + 1.5 × (wantLevel − centerLevel)
```

然后**升级和买卡同台比价**：`if (buyable[0].score < levelScore) → 升级`，否则买卡。

那个 `+3` 是拿血换来的：第 2 回合钱 5 全砸进 Lv2 → 阵容空转；第 5 回合 8 块砸进 4 本 → 剩 2 块买不起任何东西 → 19 血掉到 1 血。依据是 economy.json（首升 5 点、每回合 −1、初始 4 块、二阶卡 2 费、刷新 1 块）。

升级成功与否要**三种判据任一成立**才算：升级费变化 / 面板 x 位置变化（每级 −240）/ 商店可见卡数变化。连续错 2 次就停，不硬试。

### 4.4 刷新与冻结

- **刷新**：每回合最多 2 次（旧代码无限刷，钱够就一直刷到 0）。
- **冻结**：只在「有值得留但买不起的卡」时点，点完结束本回合。

## 5. 上场 `deployFromDeck()`

四步：**认人 → 找空可站格 → 算站位 → 拖**。

### 5.1 认人（`identifyDeck()`）

```
scanDeckChips()  → 每张牌 {x, y}（已含 +52,+99 偏移）
  ↓ 逐个轻按 1200ms
左侧详情面板 → 截图 → 全部图丢一次 names_ocr.py
  ↓ 只取「x≈26、y∈[245,305]、h≥26」那一行的大字
名字 → operator-ranges.json 查职业 + 攻击范围
```

实测 4/4 全对：`星源(术师) / 渡桥(先锋) / 灰喉(狙击) / 拜松(重装)`。名字有 OCR 错字容忍（编辑距离 1）。
> 关键细节：牌的位置**不能重复加偏移**（`scanDeckChips` 的返回值已经含偏移），否则轻按落到甲板下方、面板不换人、所有牌认成同一个人。

### 5.2 找空可站格（`scanFreeTiles()`）

不去猜坐标，**让游戏自己告诉我们哪些格空着**：

```
长按某张牌 450ms → 拖到 (300,950) 非法格 → 停 3 秒（保持持物态）
  ↓ 此时所有可放置格变绿
截图 → sidecar/freetiles.py：60×44 窗口绿占比 > 0.55 的局部极大值
  ↓ 掩掉顶部 UI / 甲板 / 左侧面板 / 右侧按钮
→ [{x, y, green}, …]（实测一帧扫出 10 个）
```

阈值是实测出来的：**空格绿 0.70–0.96；站着干员的格 ~0.25（Q 版小人挡住中心）；岩石/水面 0–0.26**。
落在非法格松手 = 不上场，不消耗部署位，所以这个探测是免费的。

> ⚠️ **能站人不等于该站人**。同代码只换站点来源的对照实验：扫空格 → R1 22(−4)/R2 16(−6)/R3 12(−4)；写死 12 格 → R4 9(−3)/R5 9(0)。原因是绿色是**整块可部署区**（含出生点半场和后排），而没地图时所有格同分，按 y 从小到大塞，人就站到敌人路线外去了。所以 `smart` 现在**默认关闭**，等 `data/maps/wz-01.json`（红门→蓝门路径格）就位再开。

### 5.3 站位打分 `placement.js`（纯函数）

```
score(格, 朝向) =
   覆盖「敌人行进路线」的格数 × w.path
 + 覆盖的友军数 × w.ally × 友军权重   （医疗专用；重装 2.0 / 近卫 1.3 / 特种 1.1）
 + 重装：离红门越近越好  w.door × max(0, 6 − 曼哈顿距离) / 6
 + 远程站高台/栅栏 +w.safe；近战站高台 −2
 + 站地面 +w.ground
站 blocked 格 = −∞
```

职业权重表 `CLASS_W`：

| 职业 | path | ally | door | safe | ground |
|---|---|---|---|---|---|
| 重装 | 1.0 | 0 | **3.0** | 0 | **2.0** |
| 医疗 | 0.3 | **2.5** | 0 | 1.5 | 1.0 |
| 狙击 / 术师 | **2.0** | 0.2 | 0 | 1.5 | 0 |
| 近卫 | 1.5 | 0 | 1.0 | 0 | 1.5 |
| 先锋 | 1.2 | 0 | 2.0 | 0 | 1.5 |
| 辅助 | 1.2 | 0.3 | 0 | 1.2 | 0 |
| 特种 | 1.0 | 0 | 1.0 | 1.0 | 1.0 |

**没有重叠惩罚**——用户明确说「范围重叠了没关系」。
**朝向**：四个方向各算一遍取覆盖路线最多的，平局朝红门。
**医疗的 ally 权重**来自用户原话（m03053）：「至少一个医疗放后排、攻击范围覆盖最前面的重装」。

### 5.4 上场顺序 `DEPLOY_RANK`（部署顺序 = 仇恨表）

2026-03-14 起的规则：部署顺序是「从上到下 > 从左到右」，而**敌人优先攻击最后部署的干员**——最后上场的那个就是全场靶子。所以：

```
医疗 2 → 术师 3 → 狙击 4 → 辅助 5 → 先锋 6 → 近卫 7 → 特种 8 → 重装 9
（脆皮先上，承伤单位最后上）
```

注意：`planDeploy` **不重排**（返回数组与入参逐项对齐），否则 chip 和落点会错位；排序只发生在拖拽队列那一层。

### 5.5 一次成功的日志长这样

```
站位计划：星源→1150,330 朝right / 渡桥→770,300 朝right / 灰喉→990,410 朝up
上场 星源 (1449,775 → 1150,330) 朝right  甲板 6→5
```

## 6. 战斗与结算

- `playRound({battleMaxMs})`：认屏 → 必要时点「准备就绪」→ 处理确认模态 → 循环等 `warbanner/wz_rest/wz_tactic/wz_settle` → 撞到 `wz_tactic` 就 `pickTactic({prefer:0})` 选掉。
- 战斗中**完全不能操作**（用户原话），所以这一段就是等 + 认。
- `readSettle()`：结算页 OCR 读「通过回合 / 卫戍认证 / 用时 / 认证上限」，落 `world/data/runs.jsonl`。
- 血量采样：每回合结束读一次，`lifeLost = max(0, lastHp − hp)`，写进战报——这是判断「这一回合的站位有没有用」的唯一指标。

## 9. 已知缺口（按优先级）

1. **vision 把休整期误判成 wz_admin/wz_hall** → 整局被提前掐断，已害 3 次。
2. **没有 `data/maps/wz-01.json`** → `smart` 站位开不了；这是「第 9 回合以后」的唯一解药。
3. **装备没自动佩戴**（每名干员最多 2 件）——用户点名要的，还没做。
4. **甲板超员不会自动卖** → 只做了「不买」，没做「卖掉换钱的」。
5. **`readSettle` 读数不稳**（13 读成 6、×160 读成 ×60）→ 现在靠人工回填。
6. 买卡打分还没有「对子优先」以外的整局节奏（什么时候该攒钱、什么时候该清仓）。
7. 还没装进 Coopanion 本体（要写 `extensions/` + config 的 worlds，装完必须重启）。

## 10. 试过但走不通的路（别再试）

- 干员立绘模板匹配认人（Q 版小人与 PRTS 图族不匹配）。
- `adb input` 系列注入拖拽（能抓起、松手不落位）。
- `sendevent` / `input motionevent` 拼手势（虚拟设备不延续）。
- `exec-out screencap`（二进制被弄坏，必须 `screencap -p` + `pull`）。
- `spawnSync(python, …, {encoding:'utf8'})`（沙箱 EPERM，必须 `stdio:'ignore'` + 落文件）。
- 用「截图哈希不同」判断画面有没有变化（棋盘背景一直在动，每帧都不同 → 白绕半小时）。改用定点像素采样。
