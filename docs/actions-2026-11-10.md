# 动作库（act.js）：一次命令做完一件事

日期：2026-11-10 · 作者：阿渊 · 状态：可用，已过 node --check

## 为什么要它
之前每个动作都在主机侧拆成「长按 → sleep → 截图 → 再长按」，一个干员上场要 5.5–7 秒，其中大部分时间花在 Node 侧等待与重新截图。
act.js 把同一类动作全部写进**一个 minitouch 命令文件**，一次 adb push + 一次 adb shell 执行到底，中间不回主机。

## 怎么用

```js
import { placeBatch, sellBatch, equipBatch, place, sell, equip, SELL_ZONE } from '../lib/act.js';

// 一次上 3 个（同一条命令内连续执行）
await placeBatch([
  { from: [1392, 742], to: [1032, 363], facing: 'right' },
  { from: [1250, 742], to: [880, 481], facing: 'up' },
]);

// 卖 / 装
await sellBatch([[1392, 742]], { to: SELL_ZONE, holdMs: 300 });
await equipBatch([{ from: [1388, 742], to: [832, 373] }]);
```

## 三类动作的手势参数（都是实测出来的，不是猜的）

| 动作 | 起手长按 | 路径 | 松手前停 | 落点修正 | 额外步骤 |
|---|---|---|---|---|---|
| 干员上场 | 450ms | 10 段 × 45ms | 350ms | 手指 = 目标格 + (33,120)（幻影偏移） | 定朝向：格心长按 450ms → 6 段 × 40ms 滑 600px |
| 装备上身 | 600ms | 12 段 × 45ms | 700ms | 无（直接落格心） | 无 |
| 拖去卖出 | 450ms | 10 段 × 45ms | 300–700ms（待统计） | 无 | 无 |

判据（缺一不可）：
- 抓起：按下的瞬间**场上干员格变绿、甲板格变青**，左侧弹详情。
- 干员上场成功：目标格上多出一个**带橙色朝向箭头**的单位。
- 装备上身成功：目标单位头顶多一条**白色横条**（装两件就是两条）。
- 卖出成功：金币 +1、甲板/场上少一个。

## 已知坑

- **商店必须折叠**：展开时甲板牌行被商店撑到 y≈897，deck.py 会把商店卡的小牌当成甲板牌。
- 折叠判据：`scanDeckChips()` 返回的牌行 y > 830 视为展开，点 (1763,953) 折叠后重扫。
- `剩余可放置角色` 不是实时预算（放上去后可能不变），不能当成功判据。
- 「当前存在无法放置的单位，在休整期结束时将被清空」指的是**未加载的召唤物**，不是甲板单位。
- run_code 会话内 import 过的模块会被缓存，改完代码必须新起 node 进程验证。
